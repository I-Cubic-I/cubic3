# 디지털판 미니게임 풀

> **실물 미니게임 풀(`MINIGAMES.md`)과 분리한다**(사용자 2026-10-14). 두 버전이 같은 미니게임을 공유하게 만드는 건 무리가 있다.
> - 같은 뿌리에서 나온 게임이 양쪽에 있어도 되지만, **각자 별도 항목**이고 **규칙을 서로 맞출 의무가 없다**. 이름도 달라질 수 있다.
> - 디지털판에만 있는 게임도 둔다(이전 결정 "디지털 전용 미니게임은 따로 켜고 끄는 모듈"(2026-10-10)을 대체).
> - **실제 동작의 기준은 코드**다(`packages/engine/src/minigames*.ts`, `mginfo.ts`). 이 문서는 목록과 설계 메모를 둔다.
> - 처음 배정(사용자 2026-10-14): 실물 풀 = `MINIGAMES.md`의 27개 전부. 디지털 풀 = 구현된 25개 + 만들 예정 2개 + 디지털 전용 후보.

## 공통

- 조작: 키보드·마우스·터치가 기본(마이크는 보류).
- 아이템 사용 UI·유예(3초)는 `GAME_NOTES.md` 디지털판 아이템 사용 UI를 따른다.
- 실물 풀의 제약(덱 장수 한도, 실물 도구로 처리 가능한 아이템 효과 등)에 묶이지 않는다.
- **표현 방향**(사용자 2026-10-14): 웬만한 미니게임은 화면 위 오버레이 조작판에서 진행하지 않고, **별도의 공간에서 플레이어(아바타)가 실제 보드 위에 올라서서 움직이는** 형태로 만든다(예: 주사위 눈 피하기는 아레나 바닥의 3×3 발판 위에 아바타가 서고, 고른 주사위 눈 모양대로 마법진이 터진다). **점수판은 화면에 고정된 UI로, 석판 디자인**(돌 질감·새긴 글자·잉크 테두리)으로 아레나 오른쪽 위에 둔다(사용자 2026-10-14). 화면 가운데를 가리는 큰 오버레이 창은 쓰지 않는다. **점수판에는 점수만** 둔다(사용자 2026-10-14). 화면 위쪽에는 **석판 한 장**을 가로로 걸친다: **얇은 직사각형(화면 폭) + 가운데 두꺼운 직사각형**이 한 덩어리이고, **높이가 바뀌는 두 곳만 부드러운 곡선**으로 잇는다(종 모양 아님). 두꺼운 가운데에 지금 할 일·남은 시간·룬 버튼(확정·발동), **왼쪽 위에는 게임 이름만**, **오른쪽 위에 이번 보상**(세로로 긴 작은 카드 — 위 숫자·아래 문양 — 를 **한 줄로**, 남은 폭에 맞춰 크기 조절)(사용자 2026-10-14). 턴·공격자 차례 표시는 점수판 머리에 작게("점수"라는 제목은 없다). 점수판의 플레이어 상태는 글자 대신 **아이콘**(공격자 = 칼, 생각 중 = 점 세 개, 준비 완료 = 체크)으로 간략히 해 폭을 줄인다(사용자 2026-10-14). **점수판은 늘 오른쪽 위**에 둔다. 화면이 작으면 **점수판·위쪽 석판이 같은 UI 배율로 함께 작아진다**(화면 1280×740 기준, 0.62~1배). **손패·아이템 카드는 해상도에 따라 더 넓게**(0.42~1.3배: 작은 화면은 더 작게, 큰 화면은 더 크게). 위쪽 석판 띠는 작은 화면에서도 너무 얇아지지 않게 해 보상 카드가 남는 폭을 채운다(사용자 2026-10-14). 가운데 칸에는 **상황마다 짧은 문구 한 줄만**(부가 설명 없음) 두고 글자를 키워 빈 곳이 없게 하며, **키보드 단축키는 고를 수 있는 물건 옆에 키캡으로** 띄운다(주사위 1·2·3은 쟁반의 칸에 고정, 계기판에 R). **이동 방향(방향키)과 확정(Space)에는 표시하지 않는다**(사용자 2026-10-14). 칸 자체는 지나치게 길거나 두껍지 않게(넓은 화면 최대 폭 460px·두께 94px). 아레나 중에는 화면 UI도 석판 안에 놓는다: **게임 아이콘(■³)은 띠 왼쪽 끝**(제목 앞)에 두고 **메뉴 버튼**으로 쓴다(기록·설정은 메뉴 안, 아래 `OPEN_QUESTIONS.md`). 테이블 카메라용 버튼(위에서 보기·기본 시점)과 라운드·목표 칩·핑은 숨기고, 한 기기에 자리가 여럿이면 **점수판에서 내 자리 줄을 눌러** 조종할 자리를 바꾼다(사용자 2026-10-14: 떠 있는 UI 정리). 검토한 안: 위 가운데 명패만, 얇은 헤더 + 따로 붙인 가운데 칸(석판 두 개처럼 보임), 가운데로 갈수록 완만히 두꺼워지는 종 모양. 검토한 안: 아레나 옆 별도 영역(아레나 화면이 좁아짐), 아레나 안 3D 석판(원근 때문에 글자가 작음). `GAME_NOTES.md`의 "공간과 미니게임 테이블"(2026-10-10, 오버레이 창에서 하지 않는다)을 넓힌 것. **지금 구현된 조작판 화면은 규칙 확인용 초안**이며, 엔진(규칙·판정)은 그대로 두고 화면만 바꾼다.
- **아이템 쓰기(모든 미니게임 공통)**(사용자 2026-10-14): 아이템 카드를 **위로 끌어 올리면** 쓴다(누르기만 하면 안내만). 쓰면 **모두에게 아이템 이름·효과 문구 컷신**. **대상이 필요한 아이템**(풍선 불기·문양 경주·위냐 아래냐·스피드·가운데 숫자·이마 위의 카드·주사위 눈 피하기)은 **쓴 뒤에 대상을 고른다**: 10초 안에 고르고, 시간이 지나면 고를 수 있는 대상 중 **무작위**(취소는 없다). 고르는 동안 그 사람의 다른 미니게임 행동은 막히고 다른 사람은 그대로 진행. 주사위 눈 피하기의 칸 봉쇄는 쓰는 순간 남은 시간이 모두 10초 늘어난다. 검토한 안: 대상 위에 바로 끌어다 놓기(대상 선택은 항상 사용 후로 하기로), 컷신 뒤 취소, 무제한 대기(자리 비움에 게임이 멈춤).
- **미니게임만 하기**(사용자 2026-10-14, 디지털 **멀티 전용**): 로비에서 [미니게임만 하기]로 미니게임 1종을 골라 **메인 턴 없이** 그것만 한다. 규칙 설명 → 미니게임 → 순위 결과 → [같은 판 다시] / [새 판] / [다른 미니게임 · 로비로]. 지금 앉은 인원(2명 이상, 그 미니게임의 인원 범위)으로 할 수 있는 것만 고를 수 있다. 구현: 엔진 `startSolo`(행동 `startSolo`), 로비 `SoloPick`.
  - **손패 숫자 카드 2장 = 이 판의 시드**(사용자 2026-10-14, 재현용): 손패와 미니게임으로 그 판의 무작위(덱 섞기·첫 선·미니게임 안의 주사위·배치)를 정한다. 끝 화면에 시드(모두의 손패)를 보여 주고 **[같은 판 다시]**(같은 손패 → 같은 판) / **[새 판]**(새 손패) / [다른 미니게임 · 로비로]. 무작위 상태를 테이블 상태에 두어 방장이 새로고침해도 같은 흐름이 이어진다. 같은 판이라도 플레이어 행동이 다르면 그 뒤의 무작위(다시 굴리기 등)는 달라질 수 있다.
  - **아이템: 모두 J 1장**(♣ 아님, 사용자 2026-10-14). 검토한 안: 아이템 없음, 방에서 고르기. (다른 방에 시드를 입력해 같은 판을 하는 기능은 아직 없음)
  - 시안에서 정한 것 **[제안]**: **보상·토큰·동점 주사위 없음**(순위만) · 규칙 설명 중 **♣로 미니게임 바꾸기 없음** · 즉시 시작 미니게임(눈치 게임)은 규칙 설명 없이 바로.

## 게임별 설계 메모

`MINIGAMES.md`의 각 게임에 붙어 있던 "디지털판" 메모를 옮겼다(2026-10-14). 날짜·사용자 표시는 원래 결정 시점이다.

### 거짓말쟁이 (liar)

- 아이템 문양이 **선언한 문양과 같을 때만** 그 아이템 카드가 활성화된다(노란 테두리, 클릭하면 즉시 발동. `GAME_NOTES.md` 디지털판 아이템 사용 UI, 사용자 2026-10-09).
- "이의 있소!" 같은 문구는 디지털판 연출로 쓸 수 있다(룰북·카드 문안에는 넣지 않는다, 사용자 2026-10-09).

### 갈림길 (fork)

- 커서로 칸을 고르는 연출.

### 버티기 (hold)

- 각자 화면에서 굴림/멈춤 버튼.

### 합이 10 (ten)

- 주사위 잡기 = 버튼(키·터치) 먼저 누르기.
- **박빙 연출**(사용자 아이디어 2026-10-09): 차이가 아주 작으면(예: 0.1초 안) 손이 엉켜 카드 더미가 흐트러지는 연출. 판정에는 영향 없음.
- 구현 메모: 한 기기에서 같이 하면 입력 순서만 보면 된다. **온라인은 통신 지연(수십~수백 ms)이 사람 반응 차이보다 클 수 있어** 서버 도착 순서로 판정하면 불공평하다. 각 기기에서 "카드가 화면에 뜬 순간부터 누른 순간까지"의 반응 시간을 재서 비교한다. 이 값은 기기가 보고하므로 조작 가능성이 있다. **조작 대책은 랜덤 매칭 멀티를 지원하게 될 때만 다시 꺼낸다**(사용자 2026-10-09). 친구끼리는 감수.
- 온라인에서는 플레이어마다 **핑을 표시**한다(사용자 2026-10-09, `GAME_NOTES.md` 플랫폼 방향).

### 눈치 경매 (auction)

- 카드 선택 후 동시 공개 연출.
- 손패 **6장**(사용자 2026-10-14, 실물과 같게. 5장이면 마지막 경매가 강제 입찰이라). 코드 `core.ts`도 6장으로 바꿨다.

### 몇 장이었지 (count)

- 화면에 카드가 1초 간격으로 지나가고, 숫자 입력 후 동시 공개.

### 금고 털기 (vault)

- 금고 3개 그림, 경비원 화면은 가려지고 도둑들이 말을 놓은 뒤 경비원이 고르면 손전등 연출.

### 뭐가 바뀌었지 (change)

- **점수는 실물판과 다르게** 한다(사용자 2026-10-11): 실물처럼 **바꾸는 사람이 돌아가며 말을 옮기고**(무작위 이동안 대체), 나머지는 모두 각자 바뀐 말을 고른다. **맞힌 말마다 1점**.
- 보드 그림 위 말 8개, 바꾸는 사람 외에는 화면 암전, 바꾸는 사람이 2개 이동, 나머지 각자 고르기. 아이템(하나 더 옮기기)은 실물과 같다.

### 주사위 쌓기 → 스태커 (stack)

실물 동작(탑 들어 올리기)을 화면에서 재현할 수 없어 조작 방식이 다르다(사용자 2026-10-10).

- **8행 5열 그리드**. 한 행에서 좌우로 움직이는 네모 LED를 멈춰 아래 칸 위에 계속 쌓는다(아케이드 "스태커" 방식).
- **끝까지(8층) 쌓은 시간**으로 순위.
- 아래 칸과 어긋나게 멈추면 **그 층부터 다시**(시간은 계속 흐름). 층이 올라갈수록 네모가 **빨라진다**(사용자 2026-10-10).
- 시간 제한, 제한 안에 못 끝낸 사람의 순위(높이 순 등)는 구현 때.

### 밸런스 게임 (balance)

- 선이 두 단어를 입력(또는 예시 목록에서 고름), 모두 버튼 2개 중 동시 선택. 음성 채팅과 잘 맞는다.

### 선 가위바위보 (rps)

- 버튼 3개 동시 선택, 선의 손과 각자 비교 연출.

### 풍선 불기 (balloon)

- 그대로 옮기기 쉽다. 풍선이 부푸는 연출.

### 몸짓 잇기 (gesture)

몸짓을 인식할 수 없으므로 **정해진 몸짓 8개를 버튼으로 고르는** 방식.

- **입력: 십자 2개, 몸짓 8개**(사용자 2026-10-12). 왼쪽 십자 = 손·팔 4개, 오른쪽 십자 = 머리·몸 4개. 4개(ASDF 한 줄)는 사이먼 게임에 가까워져 "무엇을 붙일까" 고르는 재미가 약해서 8개로 했다.
  - 키보드: 왼쪽 **WASD**, 오른쪽 **방향키**(양손).
  - 모바일: 화면 아래 양쪽에 십자 버튼 2개(가로 화면, 양엄지).
  - 마우스: 버튼 클릭.
  - 게임패드를 지원하게 되면 십자키 + 오른쪽 버튼 4개에 그대로 대응한다.
- **몸짓 8개 (예시, [제안])**: W 손 들기 · A 박수 · D 손 흔들기 · S 팔짱 / ↑ 고개 끄덕 · ← 고개 젓기 · → 어깨 으쓱 · ↓ 제자리 돌기. 버튼에는 글자 대신 몸짓 아이콘을 그리고, 키 글자는 작게 보조로 둔다. 최종 목록은 아바타 동작을 만들 때 정한다.
- **연출**: 버튼을 누르면 내 아바타가 그 몸짓을 한다. 다른 사람은 아바타를 보고 외운다.
  - **머리 위 아이콘**(사용자 2026-10-12): 방금 입력한 몸짓의 아이콘이 아바타 머리 위에 나타난다. 다음 입력이 들어오면 그 아이콘은 **흐려지며 왼쪽으로 밀려나고**, 새 아이콘이 머리 위에 뜬다. 흐린 아이콘은 **직전 1개까지만** 남고 그보다 앞의 것은 사라진다.
  - 그 밖에는 지금까지의 몸짓 줄을 화면에 보여 주지 않는다(기억 게임이므로).
- **판정**: 자동. 다수결이 필요 없다.
- **막힘**: 입력과 입력 사이 **3초** 안에 누르지 않으면 탈락 **[제안]**. 남은 시간은 작은 원형 타이머로 보여 준다.
- **아이템(건너뛰기)**: 내 차례가 시작되면, 첫 입력 전에 아이템 카드를 눌러 쓴다.

### 눈치 게임 → 서부 총잡이 결투 (nunchi)

실물(숫자 외치기)과 방식이 다르다(사용자 2026-10-12).

- **컨셉**: 서부 시대 총잡이 결투. 석양 아래 모두 대치하고 있다가, **갑작스럽게 나오는 신호**에 가장 빨리 쏘는(누르는) 사람이 이긴다.
- **즉시 시작**: 미니게임 판 주사위가 이 카드를 가리키면 바로 결투 장면으로 넘어간다(♣ 못 씀은 실물과 같다).
- **판 수·점수**: **5판**, **승점형**(사용자 2026-10-12). 판마다 1등 3점 · 2등 2점 · 3등 1점, **부정출발 -1점**. 5판 합계로 순위. (검토한 안: 목숨 3개 탈락형, 가장 빠른 사람이 1명을 쏘는 지목형)
- **한 판**: 대치 시작 → 무작위 시점에 신호 → 누른 순서대로 순위.
  - **판이 시작되고 처음 2~3초는 신호가 나오지 않는다**(긴장감, 사용자 2026-10-12). 그 뒤 무작위 시점에 나온다(상한은 시험 후, 예: 시작 후 6초까지 **[제안]**).
- **진짜 신호는 소리만**(사용자 2026-10-12): 종소리 한 번("땡!") **[제안]**. 화면에는 신호 표시가 없다. 실력은 "소리를 듣고 구분하기".
- **배경 미끼**(사용자 2026-10-12): 새가 날아감, 회전초가 굴러감, 문 삐걱, 술잔 부딪힘 등 화면 연출과 다른 소리를 섞는다. 신호 전에 누르면 **부정출발 -1점**, 그 판 순위에서 빠진다.
- **아이템: 가짜 신호**(사용자 2026-10-12): 대치 중에 낸다. 모두에게 **특이한 소리**가 울린다(종소리와 비슷할 필요는 없다). 낸 사람은 가짜인 줄 안다. (실물판은 아이템 없음.)
  - 검토한 안: 판돈 2배(위험·보상), 모래바람(남의 소리 먹먹하게), 박차 소리(나만 듣는 예고음), 결투 신청(1명 지목해 점수 뺏기).
- **판정**: 각 기기가 신호 소리가 재생된 순간(출력 지연 보정)부터 누른 순간까지의 반응 시간을 재서 서버로 보내고, 서버가 반응 시간 순으로 순위를 매긴다. 서버 도착 순서로 판정하지 않으므로 통신 지연의 영향을 거의 받지 않는다. 부정출발도 각 기기에서 "신호 소리 전 입력"으로 판단한다. 조작 대책은 합이 10과 같이 랜덤 매칭 때 다시 본다.
- 조작: 아무 키·클릭·터치 하나.
- **소리 관련 구현 메모**:
  - **블루투스 이어폰 지연**(0.1~0.3초)이 사람 반응 차이보다 크다. 브라우저의 출력 지연 값(`AudioContext.outputLatency`)으로 보정하되 기기마다 정확도가 달라 완벽하지 않다. 결투 전에 "유선·스피커 권장" 안내.
  - 브라우저는 휴대폰 무음 모드를 감지하지 못한다. 결투 전에 **"소리를 켜세요" 확인**을 넣는다.
  - 청각 접근성(소리 대신 진동·화면 신호)은 나중에 따로 본다.

### 말 컬링 (curling)

- **끝에만 벽, 양옆은 열린 구조**로 실물과 같게(사용자 2026-10-12). 아이템(박스 치우기)은 그 한 번만 벽이 사라지는 연출.
- **조작: 새총식 끌기**(당구 게임 방식, 사용자 2026-10-12). 말을 뒤로 끌어 방향과 세기를 정하고 놓는다. 마우스·터치 그대로. 키보드는 방향키로 조준, 스페이스를 누르고 있는 시간으로 세기 **[제안]**.
  - 검토한 안: 게이지 타이밍(골프 게임식, 기기 차이 없음), 스와이프 튕기기(기기 차이 큼).
  - 마우스가 터치보다 정밀해 기기별 유불리가 생길 수 있다. 시험판에서 확인.
- **연습 시간**(사용자 2026-10-12): 본 게임 전에 모두 연습해 볼 수 있게 한다. **규칙 설명 시간 안에** 각자 자기 화면에서만 보이는 연습용 말을 자유롭게 튕겨 본다(다른 사람과 판에 영향 없음). 모두 준비를 누르면 시작 **[제안]**.
- 구현 메모: 말끼리 부딪히고 미끄러지는 단순한 2D 물리면 충분하다. 온라인은 "방향·세기 입력"만 보내고 모든 기기가 같은 계산(엔진 순수 함수, 고정 시간 간격)을 돌려 결과를 맞춘다.

### 딱 10초 (디지털 전용, 만들 예정)

사용자 2026-10-14 채택. 시계가 필요해 실물에서는 못 하는 **시간 감각** 게임. 조용한 줄 서기의 "속으로 세는 감각"과 결이 같다.

- **초안**: 화면의 초시계가 **처음 3초만 보이고 사라진다** **[제안]**. 모두 속으로 세다가 **정확히 10초라고 생각할 때** 누른다. 10초에 가장 가까운 사람이 이긴다. **3판** **[제안]** 합계로 순위.
- 판정: 각 기기에서 시작 표시부터 누른 순간까지의 시간을 재서 비교한다(서부 총잡이와 같은 방식, 통신 지연 영향 적음).
- 정할 것: 점수 방식(판마다 순위 점수 / 10초와의 차이 합계), 10초를 넘긴 사람 처리(넘겨도 차이로만 볼지, 넘기면 실격일지), 아이템.

### 주사위 눈 피하기 (dodge, 가제, 디지털 전용, 구현됨)

2026-10-14 구상. 줄넘기(위협 부족) → "다 같이 무언가를 피하는" 방향(사용자) → 마리오 파티식 레퍼런스(색깔 발판·회전 막대·무너지는 바닥)는 특색이 없다(사용자) → **주사위 눈 배치가 곧 위험 지도**인 이 게임만의 장치로.

- **핵심**: 바닥이 **3×3 칸**. 공격자가 고른 **주사위 눈 모양의 칸이 폭발**하고(아레나에서는 마법진 + 빛 폭발), 그 칸에 있던 사람이 맞는다.
- **눈마다 정해진 모양을 옮기고 돌린다**(사용자 2026-10-14). 조작은 "모양을 판 위에 끌어다 놓고, 필요하면 회전"으로 통일(테트리스·블로커스처럼). "한 줄의 아무 N칸 고르기"는 칸을 하나씩 찍고 허용 여부를 따져야 해 번거로워 쓰지 않는다.

  | 눈 | 모양 | 이동·회전 | 놓을 수 있는 자리 |
  |---|---|---|---|
  | 1 | ● | 이동 | 9곳 |
  | 2 | ● · ● (띈 2칸, 사이는 비움) | 이동 + **45도 회전** | 8곳(가로 3 + 세로 3 + 대각선 양 끝 2) |
  | 3 | ●●● (1×3) | 이동 + **45도 회전** | 8곳(가로 3 + 세로 3 + 가운데를 지나는 대각선 2) |
  | 4 | 2×2 | 이동 | 4곳(어디에 놓든 가운데를 덮는다) |
  | 5 | 네 모서리 + 가운데 | **고정** | 1곳 |
  | 6 | 두 줄(양옆 세로 / 위아래 가로) | 90도 회전 | 2곳 |

  - **줄 모양(2·3)은 45도씩 돌린다**: 회전할 때마다 ─ → ╲ → │ → ╱. 2와 3에 똑같이 적용되는 규칙이라 예외로 외울 게 없다(사용자 2026-10-14 대각선 허용 제안).
  - **2는 띈 2칸**(사용자 2026-10-14): 3(●●●)에서 가운데만 뺀 모양. 양 끝 협공, 사이는 안전. 대각선으로 돌리면 일반 주사위의 2와 같은 모양. 검토한 안: 붙은 2칸(1×2, 20곳, 1을 조금 키운 느낌).
  - **구역별 피난처**: 가운데를 못 치는 눈 2·6 / 변 가운데를 못 치는 눈 5 / 모서리는 없음(늘 위험, 갈 곳도 3칸). 가운데는 갈 칸이 가장 많아 몰리기 쉽지만 치는 눈(1·3·4·5)이 넉넉해 지나치게 안전하지 않다. 세 주사위가 모두 2·6이라 가운데가 확실히 안전한 판은 약 4%.
  - **회전은 공격자가 고른다**(사용자 2026-10-14: 예측 불가능과 손맛). 검토한 안: 굴린 방향 그대로 회전 고정(조작이 가장 단순하고 수비자 퍼즐이 깊어지지만, 6·대각선 3이 자리 1곳으로 뻔해져 공격자가 약해짐).
  - 앞선 안: 일반 주사위 배치 그대로(사용자: 미니게임에서는 큐빅 홈 배치보다 일반 주사위가 직관적) → 3만 가운데를 지나는 줄 → 1~4 자유 배치 → 정해진 모양 + 이동·회전 → 2는 띈 2칸.
  - 균형 메모: 수비자가 무작위로 서면 공격 방식과 상관없이 맞을 확률은 "칠 칸 수 ÷ 9"(1칸 11% · 2칸 22% · 3칸 33% · 4칸 44% · 5칸 56% · 6칸 67%). 작은 눈은 좁지만 정확히 노리고, 큰 눈은 넓지만 모양이 읽힌다(6이면 가운데 줄 3칸, 5면 변 가운데 4칸이 안전).
- **공격자 vs 수비자**(사용자 2026-10-14): 공격자 1명이 떨어뜨릴 눈(과 칸·방향)을 몰래 고르고, 나머지 수비자들은 동시에 몰래 설 칸을 고른다. **모두 한 번씩 공격자**를 하고, 공격자 1명당 **3턴, 2인만 5턴**(사용자 2026-10-14). 전체 2인 10턴 · 3인 9턴 · 4인 12턴 · 5인 15턴(한 턴 10~15초로 약 1.5~4분). 4·5인에 5턴이면 20·25턴으로 길이 목표(2~4분)를 넘는다.

  - **공개 주사위 = 별자리**(사용자 2026-10-14): 주사위 3개는 아레나 둘레 하늘에 **별자리(잔상)**로 떠 있다(눈 = 별, 테두리·눈 사이 = 옅은 선). 넓은 화면은 아레나 **왼쪽·위·오른쪽**에 하나씩, 좁은 화면은 위쪽 한 줄. 수비자도 이걸 보고 남은 주사위를 읽는다.
  - **소모 연출**(사용자 2026-10-14): 공개 때 쓰인 주사위의 별자리가 번쩍이며 **진짜 주사위로 현실화**해 마법진 쪽으로 날아들어 빛과 함께 사라진다(발동). 잠시 뒤 그 자리에 새 별자리가 맺힌다. 공격자 시점에서는 발동하는 순간 고른 주사위가 빛나며 **수정구로 빨려 들어간다**.
  - **다시 굴리기 연출(공격자)**(사용자 2026-10-14): 빈자리에 **마법진과 함께 주사위가 나타나고**, 다 나타나면 **한 번 공중에 떠올라 회전하다가 눈이 정해지고**, 정해진 눈은 **잠깐 확대해 강조**한다. 공격자가 바뀔 때는 3개가 차례로 이렇게 나타난다.
  - **엿보기**: 공격자에게는 통제실에 **포탈이 열리고 엿본 사람의 얼굴이 튀어나와 주사위를 슥 훑고, 구름 말풍선**(쓴 주사위)으로 알아차린 뒤 돌아간다. 수비자에게는 **아이템 컷신이 먼저 끝난 뒤** 그 아바타 머리 위에 **전구**가 뜨고, 이어서 **쓴 본인에게만 하늘의 별자리가 강조**된다(공격자가 고른 주사위의 별자리가 붉게 빛나며 커지고 나머지는 흐려진다). **강조가 끝나면 전구는 모두에게서 사라진다**. 전구는 쓴 본인을 포함한 모든 수비자에게 똑같이 보인다(사용자 2026-10-14). 시각·색·크기는 [제안]: 컷신 뒤 0초 전구, 0.7~1.3초 강조, 1.7~2.0초 전구 사라짐. 예전의 "눈 감고 생각(…)" 단계는 뺐다.
  - 시안에서 정한 것 **[제안]**: 공개 연출 시간 2.6초 → 3.4초(제자리 이동 → 마법진 → 빛 폭발 → 날아감 → 포탈 복귀), 결과 글자는 빛이 터진 뒤에. 아레나 중에는 "칸 봉쇄!"·"엿보기!" 같은 화면 가운데 배너를 띄우지 않는다(아레나 연출이 대신).
- **실물 승격 검토 → 일단 디지털로만**(사용자 2026-10-14: 복잡하다). 검토 내용: 3×3 판이 없음(판 인쇄 추가나 카드 9장), 동시 비밀 선택은 "공격자가 쓸 주사위만 가림막 뒤에서 쥠 → 수비자 방향을 몰래 덮음(문양 카드 등) → 공격자가 공개로 배치 → 공개" 순서로 가능, 칸 봉쇄는 동전, 엿보기는 쥔 주사위를 보여 주기, 수비자끼리 이동 공유는 실물에서 불가.
